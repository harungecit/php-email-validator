# Contributing

Thanks for helping make **php-email-validator** better! Bug reports, missing
domains, false-positive reports, framework integrations and documentation
improvements are all welcome.

## Reporting a disposable domain that is not detected

1. Check it first: `vendor/bin/email-validator check suspicious-domain.example`
2. Open an issue (or a pull request) that adds the domain to
   [`data/blocklist.local.conf`](data/blocklist.local.conf) — one lowercase
   domain per line — together with evidence that it is a temporary/throwaway
   mailbox service (e.g. its website).

Domains in `blocklist.local.conf` survive every upstream rebuild and bypass the
popularity and typo filters, so only add genuine disposable services.

## Reporting a false positive (a legitimate domain that is blocked)

1. Find out *why* it is blocked:

   ```bash
   vendor/bin/email-validator check user@legit-domain.example
   # DISPOSABLE user@legit-domain.example (matched legit-domain.example in blocklist)
   ```

2. Open an issue or a pull request that adds the matched domain to
   [`data/allowlist.conf`](data/allowlist.conf), explaining what the domain
   is (ISP, company, university, privacy relay, …).

Allowlisted domains — and their subdomains — are removed from the blocklist on
every rebuild, so the fix is permanent. Applications can also fix it locally
right away with `lists.custom_allowlist`.

## Never edit generated files

`data/blocklist.conf`, `data/blocklist.php` and `data/metadata.json` are
generated by `composer update-lists` (see [`scripts/update-lists.php`](scripts/update-lists.php))
and rebuilt daily by the `update-lists` workflow. Edit `blocklist.local.conf`
or `allowlist.conf` instead, then run:

```bash
composer update-lists
composer test
```

## Development setup

```bash
git clone https://github.com/harungecit/php-email-validator.git
cd php-email-validator
composer install
composer test
```

- The library runtime supports **PHP 8.0+** — don't use PHP 8.1+ syntax in
  `src/` outside `src/Framework/` (CI lints the runtime on PHP 8.0).
- The test suite requires PHP 8.1+ (PHPUnit 10–12).
- Tests must not need network access; use a fake `HttpDownloader` for sync tests.
- Framework integrations live in `src/Framework/<Framework>/` and must not be
  referenced from the core, so the core never depends on a framework.
  CI runs the oldest supported framework versions on PHP 8.1 and the newest on
  PHP 8.4+, so keep integrations compatible with both.

## Coding standards

- PSR-12, `declare(strict_types=1);`, typed properties and return types.
- Full PHPDoc on public methods, matching the surrounding code.
- Every change ships with tests; `composer test` must pass.

## Pull requests

1. Fork the repository and create a feature branch.
2. Make your change with tests and documentation (README) updates.
3. Ensure `composer test` passes.
4. Open the pull request against `main` and describe the motivation.
